# Kanban

Kanban app split into two independent apps, `backend/` and `frontend/`, that talk only over HTTP. Each app has its own `package.json`, `bun.lock`, `tsconfig.json` and scripts. There is no root `package.json`, so run every command from inside the app's folder.

## Map

```
.
├── .agents/rules/            coding standards (see Rules)
├── backend/                  HTTP API
│   ├── src/index.ts          entry point: builds the Elysia app and listens
│   └── bunfig.toml           Bun config: exact versions on install
└── frontend/                 web UI
    ├── src/routes/           file-based routes: __root.tsx is the HTML shell and layout, index.tsx is `/`
    ├── src/router.tsx        router factory (`getRouter`)
    ├── src/routeTree.gen.ts  route tree generated by the TanStack Router plugin
    ├── src/styles.css        Tailwind entry
    ├── vite.config.ts        plugins: TanStack Start, React, Tailwind, devtools
    └── bunfig.toml           Bun config: exact versions on install
```

## Services

|         | backend                                         | frontend                                                                                              |
| ------- | ----------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| Role    | HTTP API: Kanban business rules and data        | UI the user works in: server-rendered React that reads and writes data through the backend API        |
| Runtime | Bun, running TypeScript directly                | Vite 8, run on the Bun runtime through `bun --bun`                                                     |
| Stack   | Elysia 1, TypeScript (strict)                   | TanStack Start + TanStack Router (file-based), React 19, Tailwind CSS 4, TypeScript 6 (strict)        |
| Port    | 3333 (`PORT` env var; default in `src/index.ts`) | 3000 in dev, 4173 in preview                                                                          |

Both apps use Bun as package manager.

## Commands

| Task                 | backend                                                    | frontend                                                          |
| -------------------- | ---------------------------------------------------------- | ----------------------------------------------------------------- |
| Install dependencies | `bun install`                                              | `bun install`                                                     |
| Add a dependency     | `bun add <pkg>` (`-d` for dev)                             | `bun add <pkg>` (`-d` for dev)                                    |
| Dev server (watch)   | `bun run dev`                                              | `bun --bun run dev`                                               |
| Type check           | `bun check`                                                | `bun check`                                                       |
| Unit tests           | `bun test`                                                 | no runner yet (see Tests)                                         |
| Build                | none: Bun runs `src/index.ts` as is                        | `bun --bun run build` → `dist/client/` and `dist/server/server.js` |
| Run the build        | `bun --no-env-file src/index.ts` (platform env vars only)  | `bun --bun run preview`                                           |

To run the whole project, start both dev servers in separate terminals: the UI at http://localhost:3000, the API at http://localhost:3333.

- Dependency versions are exact (`"elysia": "1.4.32"`). `bunfig.toml` sets `exact = true`, so `bun add` writes them that way.
- Add or change a page by editing files in `frontend/src/routes/`. The TanStack Router plugin rewrites `src/routeTree.gen.ts` on the next `dev` or `build`.

## Tests

No tests exist yet. Each unit spec sits next to the file it tests, as `<file>.spec.ts` (`.spec.tsx` for components).

- **Backend**: `bun test`, importing from `bun:test`; coverage threshold goes in `bunfig.toml` under `[test]`.
- **Frontend**: Vitest with Testing Library, as `testing-standards.md` sets. Once installed, run it with `bun run test`: plain `bun test` starts Bun's own runner instead of Vitest.
- **E2E**: Playwright, in a root `e2e/` folder with one `<flow>.e2e-spec.ts` per flow, running against both apps (`fullstack-folder-structure.md`).

## Rules

Before writing or changing code, read every rule in `.agents/rules/` whose trigger matches the change:

- **Every change**: `code-standards.md`, and `testing-standards.md` (each change ships with tests).
- **`.ts`, `.tsx`, `.js`, `.jsx` files**: `javascript-typescript-standards.md`.
- **Backend code**: `bun-standards.md`.
- **Frontend components, hooks and views**: `react-standards.md`.
- **New files or folders at the repo root, E2E specs, or deciding which app owns a piece of code**: `fullstack-folder-structure.md`.

`node-standards.md` covers Node.js backends. This backend runs on Bun, so `bun-standards.md` governs it.
